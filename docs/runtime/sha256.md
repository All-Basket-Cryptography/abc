# SHA-256 research API contract

The first provider implements portable, byte-oriented SHA-256 as specified by [FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final). It accepts byte strings of length 0 through `2^61 - 1` and returns exactly 32 bytes in big-endian word order. A rejected length leaves the stream unchanged. Chunks are processed or copied before the update returns. No input ownership is transferred.

Rust `Sha256::new` creates an empty context. `update` takes an immutable byte slice and returns `MessageTooLong` for length overflow. A mutable reference serializes updates. `finalize(self)` closes the context by consuming it. `Clone` takes an independent snapshot of an open context. The provider identifies itself as `sha256-abc-rust-portable`.

The npm WASM provider reports its implementation, target, and research status. Its input is a `Uint8Array` and a digest is a fresh `Uint8Array`. Each context belongs to its creating JavaScript environment. `dispose()` releases an open context and is idempotent. Calling `update` or `finalize` after disposal or finalization throws. Type errors and length errors leave the context unchanged. The Node consumer and browser consumer load the same WASM bytes, so neither serves as an independent core implementation.

RNG, key management, asymmetric formats, and policy-selected dispatch require their own typed interfaces and evidence. The current API accepts bytes and exposes only hashing. Production eligibility is a separate, versioned policy decision. Formal implementation refinement and target correspondence are pending.
